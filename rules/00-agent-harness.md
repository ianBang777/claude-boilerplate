# 00. 에이전트 작업 원칙 (Agent Harness)

Andrej Karpathy의 4가지 하네스 원칙. AI가 코드를 망치는 4가지 실패 모드 (말없는
가정, 과한 추상화, 무허가 수정, 모호한 성공 기준)를 막기 위한 최상위 규칙.

## 1. 코딩 전에 생각하라 (Think Before Coding)

- **가정은 명시한다** — 불확실하면 추측하지 말고 묻는다.
- **여러 해석을 제시한다** — 모호하면 말없이 하나를 고르지 않는다.
- **필요하면 반박한다** — 더 단순한 방법이 있으면 말한다.
- **헷갈리면 멈춘다** — 무엇이 불분명한지 짚고 확인을 요청한다.

## 2. 단순함이 먼저다 (Simplicity First)

- 요청받지 않은 기능은 만들지 않는다.
- 한 번만 쓰는 코드에 추상화를 넣지 않는다.
- 요청 없는 "유연성" · "설정 가능성"을 추가하지 않는다.
- 일어날 수 없는 시나리오에 예외 처리를 넣지 않는다.
- 200줄을 50줄로 줄일 수 있으면 다시 쓴다.

## 3. 외과적 수정 (Surgical Changes)

기존 코드를 수정할 때:

- 인접한 코드 · 주석 · 포맷을 "개선"하지 않는다.
- 깨지지 않은 것을 리팩터링하지 않는다.
- 내 스타일과 달라도 기존 스타일을 따른다.
- 관련 없는 죽은 코드를 발견하면 **삭제하지 말고 언급**한다.

변경으로 고아 코드가 생기면:

- 내 변경 때문에 안 쓰이게 된 import · 변수 · 함수는 제거한다.
- 기존에 있던 죽은 코드는 요청 없이 제거하지 않는다.

## 4. 목표 주도 실행 (Goal-Driven Execution)

- 모호한 지시 대신 **검증 가능한 성공 기준**을 정의한다.
- 복잡한 작업은 체크포인트가 있는 다단계 계획을 세운다.
- 기준이 충족됐음을 확인할 때까지 스스로 반복(loop)한다.
