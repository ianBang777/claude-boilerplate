# 06. 리뷰 체크리스트 (완료 게이트)

작업 완료 · 리뷰 시 점검한다. 규칙을 외우는 곳이 아니라 **위반을 잡아내는 신호**를
모은 곳이다. 각 항목은 "코드를 보고 답할 수 있는 질문"이다. 원칙의 배경은
00~05를 본다.

> 🚨 = 발견 시 재작업. 04 · 05는 해당 스택일 때만.

## 작업 범위 — [00](./00-agent-harness.md)

- [ ] 🚨 **스코프 크리프**: diff에 요청하지 않은 파일 · 기능이 섞였나? (요청은 A인데
      B · C도 건드림) → 빼낸다.
- [ ] 🚨 **무관한 변경**: 기능 수정과 무관한 포맷 · 이름 변경이 같은 diff에 있나?
      → 분리하거나 되돌린다.
- [ ] **추측 구현**: 요구가 모호했는데 질문 없이 한 해석으로 밀었나?
- [ ] **과한 추상화**: 호출처가 1곳인데 인터페이스 · 팩토리 · 제네릭 · 옵션을
      넣었나? → 직접 구현으로.
- [ ] 내 변경으로 죽은 import · 변수는 지웠고, 원래 있던 죽은 코드는 손대지 않고
      언급했다.

## 보안 · 견고함 — [01](./01-general-engineering.md)

- [ ] 🚨 **비밀값**: 키 · 토큰 · 비밀번호 리터럴이 코드 · 로그에 있나? (`sk-`,
      `password = "..."` 등)
- [ ] 🚨 **검증 없는 입력**: 외부 입력이 검증 없이 쿼리 · DOM · 셸 · 경로에
      들어가나? (SQL 인젝션 · XSS · path traversal)
- [ ] 🚨 **삼킨 에러**: `catch {}` / 로그만 찍고 정상인 척 / 실패 시 조용히 기본값
      반환? → fail fast.
- [ ] 로그 · 에러 메시지에 PII가 노출되나?

## 가독성 — [01](./01-general-engineering.md)

- [ ] **모호한 이름**: 이름만 보고 역할을 모르겠나? (`data` · `temp` · `flag`)
      boolean인데 `is/has/can`이 아니거나, 컬렉션인데 단수형인가?
- [ ] **깊은 중첩**: 들여쓰기가 3단계 이상인가? → early return · 함수 추출.
- [ ] **매직 값 · 복잡 조건**: 의미 없는 숫자 · 문자열 리터럴이 로직에 박혀 있거나,
      한 `if`에 `&&` · `||`가 3개 이상인가? → 이름 있는 상수 · 변수로.

## 설계 — [02](./02-oop-design.md) · 위반 신호로 점검

- [ ] 🚨 **DRY**: 같은 로직이 복붙으로 여러 곳에 있나? 한 곳 고치면 다른 곳도 고쳐야
      하나?
- [ ] **S (단일책임)**: 클래스 · 함수를 한 문장으로 설명할 때 "그리고"가 들어가나?
      변경 이유가 둘 이상인가?
- [ ] **O (개방폐쇄)**: 새 종류를 추가할 때 기존 `if`/`switch`를 또 수정해야 하나?
      → 다형성.
- [ ] **L (리스코프)**: 자식이 부모 메서드를 빈 구현 · 예외 던지기로 무력화하나?
- [ ] **I (인터페이스 분리)**: 구현체가 안 쓰는 메서드를 억지로(빈 본문 · throw)
      채우나?
- [ ] **D (의존성 역전)**: 상위 모듈이 구체 클래스를 직접 `new`하나? 주입받지 않나?
- [ ] **묻지 말고 시켜라**: 상태를 getter로 꺼내 바깥에서 판단 후 setter로 되넣나?
      → `if (acc.getBalance() > x) acc.setBalance(...)` 대신 `acc.withdraw(x)`.
- [ ] 도메인 로직이 프레임워크 · DB · UI를 직접 import하나?

## 테스트 — [03](./03-tdd.md)

- [ ] 🚨 **구현에 묶인 테스트**: private · 내부 메서드 호출 횟수 · 중간 상태를
      검증하나? → 리팩터하면 깨진다. 동작(결과)만 봐라.
- [ ] 🚨 **잘못된 Mock**: 도메인 객체(계산기 · 서비스)를 Mock해서 정작 로직이
      검증 안 되나? Mock은 비관리 의존성(DB · 외부 API)에만.
- [ ] **버그 수정**: 재현하는 실패 테스트 없이 바로 고쳤나?
- [ ] **헛된 대상**: getter · 단순 CRUD를 테스트하느라 정작 복잡 로직 · 경계값 ·
      예외를 빠뜨렸나?

## 프론트엔드 — [04](./04-frontend.md) · 해당 시

- [ ] **빠진 상태**: 로딩 · 에러 · 빈(empty) · 성공 중 안 그린 게 있나? (보통 에러 ·
      빈이 누락)
- [ ] **불필요한 상태**: `useState`로 든 값이 다른 state · props로 계산 가능한
      파생 값인가? → 계산해서 쓴다.
- [ ] **a11y 위반**: 클릭되는 `div`(버튼 아님), label 없는 `input`, alt 없는
      `img`가 있나?
- [ ] **불안정 key**: 리스트 key가 배열 index인가? (재정렬 시 버그)

## TypeScript — [05](./05-typescript.md) · 해당 시

- [ ] 🚨 **타입 구멍**: 새로 들어온 `any`가 있나? → `unknown` + 좁히기.
- [ ] **위험한 단언**: `as` · `!`로 타입 검사를 뭉갰나? 타입 가드로 대체 가능한가?
- [ ] **숨은 nullable**: optional · null 가능 값을 `!`로 무시했나? 경계에서
      처리했나?
- [ ] `export`되는 함수 시그니처(인자 · 반환)에 타입을 명시했나?
