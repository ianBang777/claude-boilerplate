# 04. 프론트엔드 규칙 (도메인 특화 · 선택 적용)

웹 프론트엔드 프로젝트에만 적용한다.

## 컴포넌트 설계

- 컴포넌트는 작고 한 가지 책임만. 표현(presentational)과 로직(container)을
  분리한다.
- 상태는 쓰는 곳과 가깝게(colocate) 둔다. 전역 상태는 정말 전역일 때만.
- 파생 값은 저장하지 말고 계산한다 (단일 진실 공급원).
- prop drilling이 깊어지면 합성(composition)이나 context로 푼다.

## 상태 · 데이터

- 서버 상태와 클라이언트 상태를 구분한다 (서버 데이터는 캐시·동기화 도구로).
- 로딩 · 에러 · 빈(empty) · 성공 4가지 상태를 항상 다룬다.
- 비동기 작업의 경쟁 조건(race condition) · 취소를 고려한다.

## 성능

- 측정 후 최적화한다 (불필요한 `memo`/`useMemo` 남발 금지).
- 리스트는 key를 안정적으로, 큰 리스트는 가상화(virtualization).
- 번들은 코드 스플리팅 · 지연 로딩으로 줄인다. 이미지·폰트를 최적화한다.
- 레이아웃 변경을 일으키는 작업을 batching하고, 리플로우를 피한다. → 예: 위치
  이동은 `top/left` 대신 `transform: translate()` (레이아웃 안 깨짐).

## 접근성 (a11y)

- 시맨틱 HTML을 우선한다.
- 색 대비 · 대체 텍스트 · 폼 레이블을 보장한다. → 예:
  `<label for="email">이메일</label><input id="email">` (placeholder는 레이블
  대체 아님).
