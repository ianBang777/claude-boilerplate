# 마이페어 자동메일 HTML 만들기

어드민 「HTML 입력하기」 프롬프트(`FE/apps/admin/src/domain/autoMail/utils/buildAutoMailHtmlPrompt.ts`)에서 이 스킬이 쓰는 작업 A(스티비 옮기기)·C(수정하기)만 추린 것이다. 원본이 바뀌면 이 파일을 맞춘다. `{발송 정보}`·`{변수}` 는 SKILL.md 3단계 결과로 채운다.

## 1. 목적

마이페어 어드민에 그대로 저장되어 고객에게 발송될 자동메일 본문 HTML 을 만든다. 이 HTML 은 에디터를 거치지 않고 저장되므로, 받는 사람의 메일 앱(클래식 Outlook·Gmail·모바일)에서 원본과 같은 모양으로 보여야 한다.

이 메일의 발송 정보:
{발송 정보}
  형식 — `- 발송 조건: koName` / `- 보내는 때: description` / `- 받는 사람: receiverDescription`

쓸 수 있는 변수(발송할 때 받는 사람마다 실제 값으로 바뀐다):
{변수}
  형식 — `- $%key%$ : koName`. 없으면 `- (쓸 수 있는 변수 없음 — 변수를 쓰지 않는다)`

## 2. 작업

- A. 스티비 옮기기: 스티비에서 내보낸 메일 HTML → 마이페어 자동메일로 옮긴다.
- C. 수정하기: 저장된 HTML + 바꿀 내용(문장 또는 에디터에서 문구를 고친 HTML) → 바꿀 내용만 반영한다. 에디터에서 고친 HTML 은 문구만 참고하고, 모양은 저장된 HTML 을 따른다.

HTML 을 만들기 전에, 아래처럼 판단이 갈리는 것이 있으면 한 번에 모아 번호를 매겨 묻고 답을 기다린다. 없으면 묻지 않는다. 각 질문에는 추천하는 답을 함께 적는다.

- 원본의 변수·고정 값을 어느 변수로 바꿀지 확실하지 않다 (예: `$%name%$` 이 회원 이름인지 담당자 이름인지)
- 버튼·글로 바꿀 이미지의 문구나 색을 읽을 수 없다
- 수정 내용이 어느 부분을 가리키는지 알 수 없다

질문하는 동안에는 HTML 을 출력하지 않는다.

## 3. 변환 절차

1. 구조: 표(table)로 배치한다. 바깥은 width 100% 표, 안쪽 본문은 `width:100%; max-width:630px` 의 가운데 정렬 표다.
2. Outlook: body 여는 태그 바로 뒤에 아래 여는 표식을, body 닫는 태그 바로 앞에 닫는 표식을 둔다.
   ```html
   <!--[if mso]><table role="presentation" width="630" align="center" cellpadding="0" cellspacing="0" border="0"><tr><td><![endif]-->
   <!--[if mso]></td></tr></table><![endif]-->
   ```
3. 스타일: 모든 스타일을 요소의 style 속성에 인라인으로 옮긴다. 글꼴은 `font-family: 'Malgun Gothic', '맑은 고딕', 'Apple SD Gothic Neo', sans-serif` 순서로 쓴다.
4. 버튼: 표 칸 버튼으로 만든다. `<td>` 에 배경색·안쪽 여백·모서리를 주고, 그 안의 `<a>` 에는 글자색·글자 크기·굵기만 준다. 글자가 들어간 이미지(버튼 그림·배너)는 같은 색·문구의 표 칸 버튼이나 글로 바꾼다.
5. 이미지: 마이페어 로고는 `https://myfair.co/images/globals/header/myfair-header-logo.png` 로 바꾸고 원래 표시 크기와 정렬을 유지한다. 그 밖의 스티비 서버(stibee.com) 이미지 중 바꿀 수 없는 것은 그대로 두고 바로 앞에 `<!-- 교체 필요: 원래 주소 -->` 주석을 단다. img 의 width 속성은 메일에 보이는 크기(px)와 같게 하고 alt 를 채운다.
6. 링크: 모든 `<a>` 에 `target="_blank"` 를 단다.
7. 변수 교체:
   - 원본의 다른 이름 변수(예: `$%fairTitle%$`, `$%fairShortTitle%$`, `$%name%$`)는 뜻이 같은 위 변수로 바꾼다.
   - 받는 사람마다 달라져야 하는데 고정 문구로 박힌 값(특정 박람회 이름, 특정 회원 이름, 특정 견적서 코드)이 있으면 뜻이 같은 위 변수로 바꾼다.
   - 링크 주소 안의 값도 같은 기준으로 바꾼다.
   - 맞는 변수가 없으면 바꾸지 않고, 문서 맨 앞에 `<!-- 변수 없음: 원래 값 -->` 주석을 단다.
8. 작업이 C 면 바꿀 내용만 반영하고, 나머지 요소·속성·스타일은 한 글자도 바꾸지 않는다.

## 4. 유의사항

- 원본의 문구·색·글자 크기·굵기·여백·정렬·배경·구분선·빈 간격을 임의로 바꾸거나 덜어내지 않는다.
- 화면에 보이지 않는 미리보기 문구(preheader)는 유지한다.
- 꼬리말의 회사 정보·수신 안내·광고 표기 문구는 바꾸지 않는다.
- `<a>` 에 padding·배경색을 준 버튼을 만들지 않는다. 클래식 Outlook 에서 링크 글자로만 보인다.
- 외부 CSS·웹폰트·자바스크립트를 쓰지 않는다. `<style>` 의 미디어쿼리는 모바일 보정용으로만 덧붙이고, 없어도 모양이 깨지지 않아야 한다.
- 위 변수 목록에 없는 `$%…%$` 를 새로 만들지 않는다. 그대로 저장되면 받는 사람에게 글자 그대로 나간다.

## 5. 결과물 검토

출력하기 전에 하나씩 확인하고, 어긋나면 고친 뒤 출력한다.

- [ ] `<!DOCTYPE html>`·`<html>`·`<head>`·`<body>` 가 있다
- [ ] Outlook 표식이 body 의 처음과 끝에 있다
- [ ] 쓴 변수가 모두 위 변수 목록에 있다 (제목 포함)
- [ ] 고정 문구로 남은 받는 사람별 값이 없다 (있으면 맨 앞 주석으로 알렸다)
- [ ] stibee.com 주소는 「교체 필요」 주석이 달린 것뿐이다
- [ ] 버튼이 모두 표 칸 버튼이다
- [ ] 모든 링크에 `target="_blank"` 가 있다
- [ ] 원본과 비교해 문구·색·여백·배치가 같다 (C 면 바꿀 내용만 다르다)

## 6. 아웃풋

완성된 HTML 문서 하나만 만든다. `<!DOCTYPE html>` 부터 `</html>` 까지이고, 알릴 것은 문서 맨 앞 HTML 주석으로만 남긴다.
